Folder Reader + Diff

A browser tool that compares two folders and shows what was added, removed, changed or moved, with a side-by-side diff. It runs entirely in the page and sends nothing anywhere.

Why I built it

GitHub was, and still is, a challenge for me. I am still exploring and learning it, but when I first started with HTML, apps, coding and AI I needed something for versioning right away, so I built it myself. This was one of the apps I used for that.

Load two folders and every file is marked Same, Diff, Only A or Only B, with moved and renamed files detected.
Pick one file on each side for a side-by-side or inline diff and a similarity score on content, path and SHA-256.
Export JSON and CSV reports, bundle folders into one file, and ignore files with gitignore-style rules.
How it works
Stack
Plain HTML, CSS and JavaScript, with no dependencies.
Approach
Pairs files by relative path, hashes them with SHA-256 in the browser, then scores similarity for the pair you select.
Key feature
Moved and renamed detection, plus Pack Merge to combine many folders into one de-duplicated bundle.

Lucy

A role-aware assistant that answers a project team’s how-do-I questions by searching the team’s own approved guidance and showing where each answer came from.

Quick Search for acronyms, contacts, tools, links and templates, plus a “Do I need approval?” check that names the required approver before you act.
Deep chat that blends keyword and meaning-based search, boosted by the asker’s department, segment and role. Any answer can be saved to Insights in one click.
A tool rail that fans out from the logo: WorkSphere groups links you open together, the Book of Work calculator turns a volume change into its impact over the rest of the year and the next one, three and five years, and Add New submits a contact, tool, link, project/task or acronym for admin review.
Four quadrants beside the chat: two pin slots for cards and links that you can drag between, Insights for saved answers you can rename, and Social for team updates, coming soon. Each one expands to fill the side.
Settings for icon display, temperature, notification archive and user mode, a notifications panel, an admin review queue, and a movable orb you can drag anywhere on the page.
Where AI fits
Status
AI-ready, not AI-dependent. Answers are cited results assembled from fixed templates, with no text-generating model. The embedding search is already in place, so a language model could be added on top.
Search
Sentence-transformer embeddings in ChromaDB and FAISS, plus BM25 keyword search, fused as 0.45 BM25 + 0.35 FAISS + 0.20 Chroma. It retrieves, it does not write.
Input
A question, who is asking (department, segment, role) and the team’s guidance documents.
Output
Cited result cards with source and snippet, assembled from fixed templates.
Guardrails
Deterministic ranking so the same question gives the same answer, role-based visibility, and approval rules kept in a reviewable file.

AI Admin Dashboard

One console to run all of my apps. Each app exposes the same small set of admin routes and the panel is a thin shell on top: browse and edit data, test endpoints, watch AI cost, check health, and try any AI model side by side, without the panel ever holding a master key.

Why I built it

As I explore future roles and abilities within AI, I saw a friend’s dashboard, and it led me to build out my own.

An AI Lab that sends one prompt to OpenAI, Claude or Gemini and compares the answer, token count, latency and estimated cost, with a voice test for text-to-speech.
An endpoint tester that fires an app’s real routes and shows status, timing and, for AI routes, the tokens and cost returned with each answer.
A data editor, diagnostics, dependency map and health checks, all scoped to the app you pick.
How the AI works
Providers
Three providers behind one route: OpenAI, Anthropic’s Claude and Google’s Gemini for text, plus text-to-speech on the providers that offer it. Claude is text-only, so its voice test is switched off.
Keys
API keys live only in the server’s environment. The browser sends a prompt to the app’s own admin route and the server makes the call. A missing key returns a clear error rather than a crash.
Cost
Every test goes through the same quota and spending-cap path as real users, so the test bench cannot bypass the spend limits. It adds its own limit of 10 requests a minute per admin.
Access
Each app checks its own credential. For SympliLyfe that is its signed login token plus an admin allowlist, so no single login opens everything.
Contract
Every app answers to one contract: 12 routes, one response format and one error format. Adding an app means implementing the contract, not changing the panel.
Stack
A single static HTML page in plain JavaScript. Each app serves its own admin API.

SympliLyfe

A personal life operating system that brings habits, budget, health, news and events into one app, with a companion character named Aelio.

Why I built it

It began as a way to find local events and new hobbies, then grew into a “one app fits all”, a Life Operating System.

The Hearth: a daily briefing that combines weather, calendar, habits and fitness goals into one summary.
Budget, habits and health in one app, each with an AI-written plan or tip based on what you already track.
A summoned radial navigation wheel in place of fixed tabs. Live on the web.
How the AI works
Model
OpenAI gpt-4o-mini only. An allowlist wraps the model call, so any other model name is refused before a request is sent or a cent is spent.
Features
Eight AI features share one engine: the daily briefing, budget tips, fitness plan, habit analysis, habit plan, news summary, Aelio’s milestone coaching chat, and the Learning Companion, which turns “I want to learn X” into phases, milestones, gear and local places to practise.
Output
Most features ask for structured JSON with a token budget each, and the app renders it as a screen. The coaching chat returns a short reply, capped at 200 tokens, in Aelio’s encouraging voice.
Guardrails
Every call passes one wrapper, in order: a per-feature cooldown, the daily quota, a spending cap, an emergency check and content moderation. Then the model runs, usage is recorded and the request is logged.
Safety
Crisis phrases in chat and fitness input return local emergency numbers (US 911 and 988 by default) before any model call. Moderation fails closed on chat and open on one-shot features. Fitness and finance answers carry a disclaimer.
Cost
Default caps of $5 per user per day, $100 per day and $1,000 per month overall, all configurable. Token usage and estimated cost come back with every answer.
Fallbacks
If a model call fails, each feature serves a fixed fallback, such as seasonal or financial tips, instead of an error.
Privacy
AI telemetry is stored in PostgreSQL without IP address, device details or the text of prompts and answers.

Atlas

A language-learning world where you pick a place, not a lesson. Choose a language journey (Spanish, Italian, Japanese or Arabic) and everything in the hall follows it: a market stall teaches a greeting and a dish, the study room practises what you just heard, and each evening adds a star to your own constellation. The current build is v3.3.0, and it is still being built.

Why I built it

Atlas began as a single tab inside SympliLyfe. The more I built, the more it needed: its own language journeys, its own guides, and room for voice, motion and activities. Its nature and scale were too big for a tab, so I broke it out into its own app, and all the language learning now lives there. It is still being built.

One active journey at a time, with progress kept separately for each language. A journey orb in the console names the language and switches it deliberately.
A hub with five wings: Study, Culture & Cities, Food & Mercado, Events, and Volunteer & Give Back. The Mercado has a stall for each language, with three phrases spoken aloud and the dish behind them.
“A day in the Atlas”: a seven-step guided tour from morning briefing to evening reflection, plus “Your Atlas”, which draws one constellation per journey.
How it works
Stack
Plain JavaScript with scene artwork and the browser’s own speech for the phrases. Progress is saved on the device in this build.
Approach
Language lives inside places. Two guides, Aelio and Aelia, offer one place, one phrase and one thing to practise each day. A missed day leaves a gap in the sky, not a reset.
Status
Still being built. The current build has the journeys, the hub, the guided tour and a switchable light and motion layer. All language learning lives here, not in SympliLyfe.
Next
Voice, motion and activity features, then the full build-out as its own app.

Reading list

Agentic Large Language Models (van Duijn, van der Meer, Plaat and van Stein, 2026). A free textbook (CC0) on how language models take actions and work together as agents.
Introduction to AI Safety, Ethics and Society (Dan Hendrycks, 2024). Readable online in full, with an audiobook on Spotify.
Training deck

A self-study deck I wrote on enterprise AI architecture: how language models work, how APIs and tool use work, retrieval, agents and MCP, and what a deployment needs around the model.

246 slides across eight modules, with formula sheets, a glossary, scenario drills and a final exam.
Every formula is worked by hand with numbers: softmax and temperature, BM25, chunk counts, compounding errors, caching cost.
Figures are dated and sourced to Anthropic and MCP documentation. About 11.5 hours for a careful first pass.
